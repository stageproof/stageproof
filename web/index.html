Check a chart upgrade
before you merge it.

helm lint and helm template read the new chart on its own. They do not know which version you run, which values you set, or which Kubernetes version your cluster runs. Stageproof compares the two and exits 0, 1, or 2.

01 Why a green chart check is not enough

Helm does not compare the upgrade.

Three failures come from that gap. Stageproof looks for them while the change is still a pull request.

Valueshelm.values.silently_dropped

A setting you rely on stops working

The new chart renames or removes a values key. Helm ignores the old key without an error, so your override is no longer applied.

APIk8s.api.removed

The chart uses an API your cluster no longer serves

Kubernetes removes old API versions over time. A chart that still emits one fails when it is applied.

Upgradek8s.upgrade.immutable_selector_changed

The upgrade cannot be applied in place

Some fields cannot change on a running workload, such as the label selector of a Deployment. A fresh install works. The upgrade fails.

02 What ships

One command. Two charts. A result you can gate on.

stageproof check compares two chart directories, or an Argo CD Application. stageproof check-pr finds the charts a git diff touched and checks each one.

CheckQuestionWhen
Chart renderingDoes the new chart render with your values?Every run
ValuesDoes every key in your values file still have an effect?When you pass a values file
Kubernetes APIsDoes the chart use an API your version has removed?Every run
In-place upgradeDoes the upgrade change a field Kubernetes will not change?When you give the current chart
CRD sizeIs a CRD too large for client-side apply?Every run. A warning, not a block.
Live rehearsalDoes install, upgrade, and rollback succeed in a temporary kind cluster on this machine?Only with --live

The values check reads chart templates. It does not render the chart twice per key. A real API server is not started for the file checks. Both of those are on the roadmap, and neither is claimed as done.

03 Results

Four names. Three exit codes.

A file check that passes is a success. It is not a warning. The report says checked: files so you can see that no cluster was used.

PROVENexit 0

File checks passed, and the upgrade and the rollback both worked in a temporary cluster. checked: files, live cluster.

PASSEDexit 0

File checks passed. The upgrade was not rehearsed, or the rehearsal stopped for a reason outside the chart.

BLOCKEDexit 1

The upgrade has a problem the report names. A CI job should fail.

NOT CHECKEDexit 2

The check did not finish, or --require-rehearsal was set and no rehearsal ran. A CI job should fail. It does not say the upgrade is unsafe.

04 Scope

Kubernetes upgrades.

Supported

A Helm chart in a directory. An Argo CD Application that names one remote chart, including a Terraform .yaml.tmpl with placeholders. A pull request, by reading git diff. It does not call Renovate or GitLab to find out what changed.

Not supported

Terraform providers and modules. Container image contents. Kustomize, Flux HelmRelease, Helmfile, and plain manifests. Language packages.

What --live does

It starts a temporary kind cluster on the machine running the command, installs the current chart, upgrades to the new chart, rolls back, and deletes the cluster. It does not commit, and it does not change a cluster you already have. The same command on a CI runner does the same thing there.
