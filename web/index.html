01 Zero setup

One binary scans any upgrade in seconds.

You do not need a staging cluster, a kubeconfig, or an account. Download the binary and run a check right away. A config file is only for listing the values files a pull request should check.

Step 1 · Install

One free binary

Install via Homebrew, as a Helm plugin, with Docker, or grab a signed Linux, macOS, or Windows binary from GitHub Releases.

Step 2 · Run

Point at any upgrade

Give it a public chart repo, two local folders, a git pull request, an Argo CD Application, a Flux HelmRelease, or rendered YAML.

Step 3 · Decide

Local Kubernetes API check

Stageproof runs a local Kubernetes API server for your minor version, tests the upgrade in memory, and exits 0, 1, or 2.

Downloads both chart versions and checks the upgrade on your machine. Nothing is installed in a cluster. -f is your values file. --values is the same flag. Drop the last line to check the chart's own defaults.

# No checkout and no cluster. -f is your values file. --values is the same flag.
stageproof check \
  --repo https://kubernetes-sigs.github.io/metrics-server/ \
  --chart metrics-server \
  --from 3.12.2 --to 3.13.0 \
  --current-k8s 1.35 \
  -f values.yaml # your values file

Run this inside the git checkout. It reads the diff and checks every changed Helm chart, Argo CD Application, and Flux HelmRelease. It does not guess a values file. A chart is rendered with its own values.yaml until .stageproof.yaml lists the files you deploy. stageproof init writes that list: values.yaml, values-*.yaml, and files in ci/. Argo CD and Flux use the values files those manifests already name.

# In your checkout. Reads the git diff. Does not contact your cluster.
# A chart uses its own values.yaml until .stageproof.yaml lists your files.
# Argo CD and Flux use the values files those manifests already name.
stageproof check-pr \
  --current-git origin/main \
  --current-k8s 1.35 \
  --next-k8s 1.36

This runs the same check-pr on every pull request. The action checks out the pull request, downloads the binary, and posts one comment. It has no values-file input. A chart uses its own values.yaml until .stageproof.yaml lists yours. Argo CD and Flux use the values files those manifests name. current-k8s is the Kubernetes version you deploy to. Do not run it from pull_request_target.

# Same check as: stageproof check-pr
# No values-file input. A chart uses its own values.yaml until
# .stageproof.yaml lists your files. Argo CD and Flux use the
# values files those manifests name.
# current-k8s is the Kubernetes version you deploy to.
name: stageproof
on:
  pull_request:
permissions:
  contents: read
  pull-requests: write
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: stageproof/action@v1
        with:
          current-k8s: "1.35"

This runs the same check-pr on merge requests, with the same values rules as the pull request command. current_k8s is the Kubernetes version you deploy to. A note on the merge request needs STAGEPROOF_GITLAB_TOKEN. CI_JOB_TOKEN cannot write notes. The check still runs, and the report is a job artifact.

# Same check as: stageproof check-pr
# No values-file input. A chart uses its own values.yaml until
# .stageproof.yaml lists your files. Argo CD and Flux use the
# values files those manifests name.
# current_k8s is the Kubernetes version you deploy to.
# A merge request note needs STAGEPROOF_GITLAB_TOKEN.
include:
  - component: gitlab.com/zarovvvv/stageproof/stageproof@1
    inputs:
      current_k8s: "1.35"

This adds a badge to Helm pull requests. The badge is the public index report for that chart pair, and those reports use chart defaults. It does not read your values file. To check the file you deploy, use stageproof check -f or check-pr with .stageproof.yaml.

02 Why green lint still breaks production

Helm never compares the old release with the new one.

helm lint and helm template inspect the new chart in isolation. Real outages happen in the diff between what is running and what you are about to apply.

Valueshelm.values.silently_dropped

Your production override stops working

The chart renames or drops a values key. Helm silently ignores your old key with exit 0, and your setting disappears on deploy.

Upgradek8s.apply.immutable_field

A fresh install passes, the upgrade fails

Changed Deployment selectors, immutable Job pod templates, StatefulSet claim templates, or deleted PVCs fail when applied over a running release.

APIs & Imagesk8s.api.removed

Removed APIs, broken CRDs, missing tags

Stageproof checks every object against a real local Kubernetes API server, diffs CRD schemas, and verifies new container image tags exist.

03 What one binary checks

Everything ships in v0.4.0. Free and local.

Every check below runs inside the same binary. Pass --offline to skip registry lookups, or --api-server off for an offline table-only check.

CheckWhat it catchesHow it runs
Chart renderingTemplate failures on Helm 3 or Helm 4, and render diffs between the twoEvery chart run (add --helm-compare for Helm 4 diff)
Values proofKeys in your values files that the new chart silently ignores, renames, or changes-f, files listed in .stageproof.yaml, or the values an Argo CD or Flux file names. Otherwise the chart's own values.yaml
Local API serverRemoved Kubernetes APIs, immutable fields, invalid updates, and broken CRD upgradesDefault (--api-server auto downloads and caches the K8s minor)
Impact & CRDsDeleted PVCs, Namespaces, or CRDs, incompatible CRD schema changes, restarts, privilege changesEvery run
Image tagsMissing container image tags or wrong node architecture for new or changed imagesDefault (HTTP HEAD only; skip with --offline)

04 Results

Four clear verdicts. Three exit codes.

Any CI job that fails on a non-zero exit code already knows what to do.

PROVENexit 0

All file checks passed, and a temporary kind cluster installed, upgraded, and rolled back cleanly.

PASSEDexit 0

All checks passed. No live cluster was started (the report notes checked: files or API server).

BLOCKEDexit 1

A breaking change was found. The report names the exact rule, object, and reason. CI fails.

NOT CHECKEDexit 2

The check could not finish (bad flag, unreachable repo, or --require-rehearsal without kind). CI fails.

05 Simple & honest

Free to run everywhere. Clear about what it does.

100% free & open source

Licensed under Apache-2.0. The CLI, GitHub Action, GitLab CI component, Helm plugin, Renovate preset, and 300-chart public index are all free with no seat limits, no accounts, and no telemetry.

Your cluster stays untouched

Everything runs on your laptop or CI runner. Charts and values never leave your machine, no AI model is called, and production clusters are never modified. Even --live only creates and deletes a local temporary kind cluster.

Focused on Kubernetes upgrades

Built for Helm charts, Argo CD Applications, Flux HelmReleases, and rendered manifests (--before / --after). It does not check Terraform providers, container image internals, Kustomize directly, or language packages.
