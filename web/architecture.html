ARCH How a check runs

One program. It renders, compares, and optionally rehearses.

Stageproof is a command line tool. It runs on your laptop or in your CI job. The steps below are what stageproof check does on one pair of charts.

01 The path of one check

Files first. A cluster only if you ask.

chart directories, or one Argo CD Application
        |
        v
helm template  (current chart, then new chart, at --current-k8s)
        |
        v
values keys    (templates of the new chart still reference your keys?)
        |
        v
API rules      (removed APIs, immutable selectors, oversized CRDs)
        |
        +-- blocker found ---------------> BLOCKED          exit 1
        |
        +-- --live not set --------------> PASSED           exit 0
        |                                  checked: files
        |                                  (NOT CHECKED, exit 2, if --require-rehearsal)
        |
        v
kind cluster on this machine
  install current -> upgrade to new -> roll back -> delete cluster
        |
        +-- upgrade or rollback failed --> BLOCKED          exit 1
        |                                  checked: files, live cluster
        +-- rehearsal could not start ---> NOT CHECKED      exit 2
        +-- both steps passed -----------> PROVEN           exit 0
                                           checked: files, live cluster

stageproof check-pr runs that path once per changed chart. A file the pull request deleted is still a change when it sat inside a chart. The pull request result is the worst of those results: BLOCKED, then NOT CHECKED, then PASSED, then PROVEN. Rendered manifests skip the Helm steps. The API server, the impact check, and the API table still run. --live is not available for that mode.

02 Where each answer comes from

Say what is computed, and what is a table.

StepHowLimit
Render Stageproof calls helm template with your values and the Kubernetes version you named. A chart that does not render is BLOCKED for the new chart, and NOT CHECKED for the current chart.
Values It walks the Go templates. An exact path stays "proof": "templates". A key the reader cannot decide is rendered with the value, without it, and with another value of the same type when yours matches the default. A key with an effect in the current chart and none in the new chart is helm.values.silently_dropped with "proof": "render". The report does not print your values. A probe that values.schema.json rejects is not a finding. --values-proof full render-tests every key. The default mode does not.
Helm 4 --helm-compare renders with a second helm binary and compares the parsed objects. A Chart.yaml apiVersion of v3 is a warning. A post-renderer, a registry login, and a renamed Helm flag are not in the chart. A new Helm 4 install uses server-side apply. An upgrade of a Helm 3 release stays client-side unless --server-side-apply is set.
Image tags A new or changed image is asked of the registry named in that reference, with HTTP HEAD. A manifest list is read only to see whether linux/amd64 is present. Layers are not downloaded. An unchanged tag is not asked. A 401, a 403, a timeout, or a rate limit is not a block. --offline sends nothing and does not change --api-server.
Kubernetes APIs A local API server of the minor you named applies the current objects and dry-runs the new ones. Deprecations, label selectors, and the CRD size check still come from the built-in table. The server is not your cluster. The patch it ran is named in the report. --api-server off uses only the table. Webhook configurations are not sent.
Impact It compares the two sets of objects. A delete of a PersistentVolumeClaim, a Namespace, or a templated CRD is BLOCKED. A CRD schema break that an existing object uses is BLOCKED. A restart is named and does not block. When the API server did not run, the check says it compared the rendered objects. The comparison does not print values. A CRD under crds/ is judged as plain Helm, which does not upgrade that directory. An Argo CD check warns when skipCrds is false or absent, and uses the Helm rule when skipCrds is true. A Flux check reads spec.upgrade.crds. Omitted and Skip block an incompatible change. Create warns. CreateReplace is info. Rendered manifests have no chart crds/ directory.
Argo CD An Application is parsed. A remote chart is pulled. A Git path in this checkout is read at the revision being compared. valueFiles, values, valuesObject, parameters, and releaseName follow Argo CD's order. valuesObject replaces values. ${...} placeholders in a .yaml.tmpl are replaced with fixed samples so the file parses. Another Git repository is not cloned. An ApplicationSet is NOT CHECKED. A missing values file is NOT CHECKED unless ignoreMissingValueFiles is true.
Flux A HelmRelease is parsed. A Helm repository or an OCI chart is pulled. A GitRepository in this checkout is read at the revision being compared. valuesFrom and spec.values follow Flux order. A targetPath entry overwrites earlier values, including inline values. Another Git repository is not cloned. A missing valuesFrom object is a warning and the result stays PASSED. A missing chart valuesFiles entry is NOT CHECKED unless ignoreMissingValuesFiles is true. Secret values are not printed. An encrypted Secret is not decrypted.
Pull request git diff base...head lists changed files. Stageproof walks up to Chart.yaml, or recognizes an Application or a HelmRelease. One comment and one JSON report cover every chart. Kustomize and loose manifests are ignored. A deleted file inside a chart is still that chart. A deleted HelmRelease is NOT CHECKED.
Brief The terminal report and the Markdown comment list Deletes, CRDs, Privilege, Exposure, Values, Restarts, and Not checked before the check list. An empty section is left out. The lines are the finding messages and the reasons a check did not finish. It does not call a model. The result line still says 0 AI calls. The v0.1.8 binary does not print this summary.
SARIF --format sarif prints one SARIF 2.1.0 log. A pull request check puts every chart in that log. --out stays the JSON report, and that JSON matches docs/report.schema.json. A blocker is error, a warning is warning, and info is note. The message is the finding message. The exit code is unchanged. The v0.1.8 binary does not have this format.
Ignores and policy .stageproof.yaml can ignore a rule until a date, or map a rule id or a prefix to block, warn, or info. check-pr reads that file from the base ref. An ignored finding stays in the report with the reason and the date. It does not make the result BLOCKED. An expired entry does not match. A change to the file in the pull request is config.changed_in_pr and does not change the check. The v0.1.8 binary does not read these settings.
Cluster facts stageproof facts export reads a kubeconfig you pass. The calls are get and list. --cluster-facts sets the Kubernetes version when --current-k8s is absent, preloads those custom resource definitions on the local API server, and passes stored versions and node architectures into the check. Values and Secret contents are not written. Helm release Secrets are read only with --helm-releases, and only the chart name, version, appVersion, release, and namespace are kept. The file is not read from git. The v0.1.8 binary does not have this command.
Explain stageproof explain prints the level, the meaning, and what to do for one rule id. The findings page is the same text. It does not run a check and it does not use the network. An unknown id exits 2. The v0.1.8 binary does not have this command.
Live rehearsal kind starts a cluster on the requested minor version when Docker Hub has a node image. Helm installs, upgrades, and rolls back. Pods that crash stop the wait early. kind starts a real node container. An unprivileged CI job cannot do that, and the check stays on the files. The cluster is empty. A private image, a missing Secret, or a missing CRD stops the rehearsal. That is PASSED with a reason, or NOT CHECKED when --require-rehearsal is set. It is not BLOCKED.
