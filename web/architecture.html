ARCH How a check runs

One program. It renders, compares, and optionally rehearses.

Stageproof is a command line tool. It runs on your laptop or in your CI job. The steps below are what stageproof check does on one pair of charts.

01 The path of one check

Files first. A cluster only if you ask.

chart directories, or one Argo CD Application
        |
        v
helm template  (current chart, then new chart, at --current-k8s)
        |
        v
values keys    (templates of the new chart still reference your keys?)
        |
        v
API rules      (removed APIs, immutable selectors, oversized CRDs)
        |
        +-- blocker found ---------------> BLOCKED          exit 1
        |
        +-- --live not set --------------> PASSED           exit 0
        |                                  checked: files
        |                                  (NOT CHECKED, exit 2, if --require-rehearsal)
        |
        v
kind cluster on this machine
  install current -> upgrade to new -> roll back -> delete cluster
        |
        +-- upgrade or rollback failed --> BLOCKED          exit 1
        |                                  checked: files, live cluster
        +-- rehearsal could not start ---> NOT CHECKED      exit 2
        +-- both steps passed -----------> PROVEN           exit 0
                                           checked: files, live cluster

stageproof check-pr runs that path once per changed chart. The pull request result is the worst of those results: BLOCKED, then NOT CHECKED, then PASSED, then PROVEN.

02 Where each answer comes from

Say what is computed, and what is a table.

StepHowLimit
Render Stageproof calls helm template with your values and the Kubernetes version you named. A chart that does not render is BLOCKED for the new chart, and NOT CHECKED for the current chart.
Values It walks the Go templates and records which .Values keys they read. A key used by the current chart and not by the new one is helm.values.silently_dropped. This is not the same as rendering with and without the key. A key that is read and then ignored can still look used. Rendering-based proof is planned.
Kubernetes APIs A table of removed and deprecated APIs, plus a diff of label selectors and a size check on CRDs. The table is ours to maintain. It is not a Kubernetes API server. An API server of your cluster's version is planned.
Argo CD An Application file is parsed, both chart revisions are pulled, and inline helm.values are checked. ${...} placeholders in a .yaml.tmpl are replaced with fixed samples so the file parses. One chart source. Several sources, valueFiles, and a Git path as the source are not read.
Pull request git diff base...head lists changed files. Stageproof walks up to Chart.yaml, or recognizes an Application file. One comment and one JSON report cover every chart. Flux, Kustomize, and plain manifests are ignored.
Live rehearsal kind starts a cluster on the requested minor version when Docker Hub has a node image. Helm installs, upgrades, and rolls back. Pods that crash stop the wait early. The cluster is empty. A private image, a missing Secret, or a missing CRD stops the rehearsal. That is PASSED with a reason, or NOT CHECKED when --require-rehearsal is set. It is not BLOCKED.

03 Planned, and not built

The next engine is still a plan.

These are the checks we intend to add. None of them run today. The roadmap is the list, in order.

Values proof by rendering

Render with and without each key you set. A key is used when removing it changes the output. A verified rename is one that reproduces the old output.

A real API server

Apply the current objects, then dry-run the new ones, on the API server of your Kubernetes version. Removed APIs, unknown fields, and immutable fields come from Kubernetes.

What the upgrade does

A classifier for deletes, restarts, exposure, privilege, and CRD compatibility. The first lines of a report should say what the upgrade removes.
