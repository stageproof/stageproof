SEC Local & private by default

Runs on your machine. No account. Does not phone home.

Stageproof is a free, open-source CLI with no hosted backend. Your charts, values, and results stay on your laptop or CI runner. Here is exactly what the binary reads, runs, and touches on the network.

01 File checks

Read charts. Call Helm. Write a report.

ActionWhat happens
ReadsThe chart directories you name, the values files you pass, the manifest files you pass to --before and --after, Argo CD Application files, Flux HelmRelease files and the source, ConfigMap, and Secret YAML they name, .stageproof.yaml in the working directory, and, for a pull request, files from git. Secret values are not printed.
Runshelm template and, for an Argo CD Application, a Flux Helm repository or OCI chart, or stageproof check --repo, helm pull. Helm executes chart templates. Treat a chart as code. --repo downloads the two versions you name from the http://, https://, or oci:// URL you pass and deletes them when the command exits. --offline does not skip that download. --helm-compare runs a second helm binary on this machine and does not add a network call. Manifest mode does not call Helm. A Git repository that is not this checkout is not cloned. With --live, smoke commands in .stageproof.yaml run as sh -c in the temporary cluster. check-pr reads that list from the base ref, so a command added only in a pull request does not run.
WritesThe report on standard output, and the files you name with --out and --comment-file. It does not commit, push, or edit the chart. stageproof mcp writes protocol messages on stdout and logs on stderr. It does not write a report file.
NetworkCharts that are already on disk need no network for registry checks when you pass --offline, and no API server download when you pass --api-server off. Those two flags are independent. stageproof check --repo runs helm pull against the repository URL you pass (http://, https://, or oci://). That host is not fixed. --offline does not skip the chart download. A new or changed image tag is asked of the registry named in that reference with HTTP HEAD. A manifest list is fetched only to see whether linux/amd64 is present, or each node architecture from --cluster-facts when that file lists nodes. Layers are not downloaded. The host is whatever the chart rendered. An unchanged image is not asked. The default check downloads kube-apiserver, etcd, and kubectl for the Kubernetes minor you named, from the controller-tools envtest index on raw.githubusercontent.com and the release assets on github.com. The SHA-512 in the index is checked before unpacking. The files are cached. --api-server-dir uses binaries already on disk. Pulling a remote chart, or looking up a kind node image when you pass --live, also uses the network. The corpus replay command, which is not in the release binary, fetches the public commits named in its case file from github.com. stageproof facts export reads the cluster named by --kubeconfig and --context. It does not open the default kubeconfig. The calls are get and list. Helm release Secrets are read only with --helm-releases, and values are not written. stageproof comment posts or updates one comment. GitHub calls go to api.github.com or GITHUB_API_URL. GitLab calls go to the host in CI_API_V4_URL, or to gitlab.com. The token is not printed, and a redirect to another host is refused. The body is the Markdown file you pass. The chart and the values are not sent. stageproof mcp does not open a port and does not add a host. A check it runs uses the same hosts as stageproof check. Its api_server argument defaults to off.
TelemetryNone. The CLI does not report usage.

02 The live rehearsal

A temporary cluster on the same machine.

--live asks kind to create a cluster, then asks Helm to install the chart into it. The chart's images are pulled and its pods start. Hooks in the chart run. Any smoke commands in the base .stageproof.yaml run after the upgrade and before the rollback, with KUBECONFIG set to that temporary cluster. When the check ends, the cluster is deleted unless you passed --keep-cluster.

Your clusters are not the target

The rehearsal uses a kubeconfig file that Stageproof creates for that run. It does not read or change your default kubeconfig, and it does not point kubectl at a cluster you already have. facts export is the command that reads a cluster you name. You pass --kubeconfig and --context. The calls are get and list. The default role does not include Secrets. --helm-releases needs a second role, deploy/facts-helm-releases-clusterrole.yaml, and lists only Secrets of type helm.sh/release.v1.

CI is the same command

--live starts a real Kubernetes node, and that node has to set up networking and start more containers. An unprivileged CI job cannot do that, so it stays on the file check. A passing job does not merge code and does not upgrade the cluster you deploy to.

Charts can use the network

An image pull, a chart dependency, and a hook can open connections from the machine that runs the check. Run --live on a runner you trust with that chart.

03 What this page does not claim

The check runs on your machine.

  • Stageproof does not send chart files or results to a Stageproof service.
  • AI is not called. A result is computed by the checks above.

The boundary is the machine you choose to run the CLI on.
